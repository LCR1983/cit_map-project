# 🐳 Docker インフラストラクチャ ＆ ネットワーク仕様書

## 1. システムアーキテクチャ概要
本プロジェクトは、開発体験の向上と環境の差異をなくすため、完全な **Dockerマルチコンテナ・アーキテクチャ** を採用しています。
`docker-compose.yml` によってオーケストレーションされ、複数のサービスが独立したコンテナとして連携動作します。

## 2. コンテナ構成 (Services)

### 2.1. `frontend` (Nginxコンテナ)
*   **ベースイメージ:** `nginx:alpine` (軽量・セキュア)
*   **役割:** 
    *   静的ファイル (HTML, CSS, JS, 画像) の高速配信。
    *   APIリクエストのルーティング（リバースプロキシ機能）。
*   **ポートマッピング:** `80:80` (ホスト側の80番ポートをコンテナの80番へ転送)
*   **ビルド設定:** `./app/frontend/Dockerfile` にて静的リソースを `/usr/share/nginx/html` にコピー。
*   **リバースプロキシ設定 (`nginx.conf`):**
    *   `/api/` プレフィックスの付いたリクエストを、同一ネットワーク内の `backend:8080` へフォワードします。
    *   これにより、CORS（Cross-Origin Resource Sharing）の複雑な設定を回避し、同一オリジンポリシー下で安全に通信を行います。

### 2.2. `backend` (Spring Boot コンテナ)
*   **ベースイメージ:** `eclipse-temurin:21-jre` (Java 21 実行環境)
*   **ビルドフェーズ (Multi-stage build):**
    1.  `maven:3.9.6-eclipse-temurin-21` を使用してソースコード（`pom.xml` と `src/`）からJARファイルをコンパイル・パッケージ。
    2.  実行専用イメージ（JRE）にビルド済みJARをコピーし、イメージサイズを極限まで軽量化。
*   **役割:** ビジネスロジックの処理、DB接続、外部AI APIへの通信、セッション管理。
*   **ポートマッピング:** `8080:8080`

### 2.3. `mysql` (データベースコンテナ)
*   *(※現在はローカルホスト上のMySQLを利用していますが、Dockerコンテナ化する場合の標準仕様を記載します)*
*   **ベースイメージ:** `mysql:8.0`
*   **役割:** 特産品データやユーザー評価データの永続化。
*   **環境変数 (Environment):**
    *   `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_ROOT_PASSWORD` を設定。
*   **ボリューム (Volumes):**
    *   `mysql-data:/var/lib/mysql` をマウントし、コンテナ破棄時にもデータが消えない「永続化」を実現。

### 2.4. `ollama` (ローカルAIサーバー)
*   *(※現在はWindows/Macのホスト側で実行中のOllamaを参照する仕様となっています)*
*   **連携パス:** バックエンドコンテナから `host.docker.internal:11434` を経由してホスト側のAIモデル (Gemma2:2b) にアクセスします。

## 3. ネットワーク設定 (Networks)
*   **ネットワーク名:** `app-network` (ブリッジネットワーク)
*   **仕様:** 
    *   `frontend` と `backend` の双方がこの内部仮想ネットワークに参加しています。
    *   これにより、コンテナは互いをIPアドレスではなく「サービス名（`http://backend:8080/` など）」で名前解決（DNS機能）して通信することが可能です。
    *   外部（インターネット）からはフロントエンドのポート80以外は直接アクセスできず、高いセキュリティを担保しています。

## 4. 起動・ビルド運用コマンド
```bash
# 全コンテナのビルドおよびバックグラウンド起動
docker compose up --build -d

# ログの確認 (バックエンドのみ)
docker compose logs -f backend

# コンテナの停止と削除
docker compose down
```
